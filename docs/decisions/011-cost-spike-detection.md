# ADR-011: 비용 급증일 판정 규칙

- 상태: 제안 (2026-11-04, 이슈 #29)

## 배경
- S06은 비용이 갑자기 늘어난 날을 배너·빨간 막대로 보여 주고, 그날 상세(S06-6)에서 원인 서버를 짚어 줘야 한다.
- 프론트는 계산하지 않는다. 판정·배율·원인을 백엔드가 내려준다. 알림(S14)도 같은 판정을 쓴다.
- 비용은 사용 시간 × 온디맨드 단가의 추정치라, 비용이 늘었다면 어떤 서버의 사용 시간이 늘어난 것이다.

## 결정
- 평소 = 그날 직전 30일 중 기록 있는 날(기록 시작일 이후, **처음 사용한 날부터**)의 하루 추정 비용 **중앙값**.
  평균은 급증일 하루에 끌려 올라가므로 중앙값을 쓴다. 기록 시작일 앞의 0원은 "안 썼다"가 아니라 "모른다"라 넣지 않는다.
  처음 쓰기 전의 0원도 넣지 않는다. 넣으면 서버를 켠 지 보름쯤 된 날 30일 창에 0원과 쓴 날이 반씩 섞여 중앙값이 낮아지고,
  평소대로 쓴 날이 급증으로 잡힌다. 처음 사용한 날은 조회 기간이 아니라 저장된 전체 기록에서 찾아, 조회 기간이 달라도 같은 날의 판정이 같다.
  처음 사용한 뒤 꺼 둔 날의 0원은 평소에 넣는다. 쓴 기록은 있는데 단가를 하나도 모르는 날은 "모름"이라 평소·판정 대상에서 뺀다. (이슈의 "기록 시작일 이후" 정의를 이렇게 좁혀 해석했다 — 팀 확인 필요)
- 급증 = 그날 비용 ≥ 평소 × 1.5. 평소를 잰 날이 7일 미만이거나 평소가 0이면 판정하지 않는다 (근거가 약하거나 배율을 정할 수 없다).
- 원인 서버 = 그날 사용 시간 − 자기 평소(같은 30일의 하루 사용 시간 중앙값)가 가장 큰 인스턴스. 늘어난 서버가 없으면 원인을 비운다.
- 진행 중인 오늘도 판정한다. 아직 하루가 끝나지 않아 비용이 작게 잡히므로, 오늘 이미 기준을 넘었다면 확실한 급증이다.
- 저장하지 않고 조회할 때 계산한다. 일별 조회는 기간 앞 30일을 함께 읽어 첫날부터 판정하고,
  대시보드는 최근 30일 중 가장 최근 급증을 `latestSpike`로 준다.
- 체험 모드는 같은 domain(`SpikeDetector`)을 쓰고, 급증을 재현하도록 `MONTHLY_SPIKE`(매달 12일 24시간) 스케줄을 둔다.

## 결과
- 새 API 권한이나 저장 테이블 없이 동작한다.
- 서버를 처음 켠 뒤 7일 동안은 판정하지 않는다. 이미 쓰던 계정에서 서버를 하나 더 켜 비용이 오른 날은 급증으로 잡는다 (실제로 비용이 늘었으므로).
- 배율 1.5·기간 30일·최소 7일은 `SpikeDetector` 상수다. 바꾸면 이 ADR과 docs/API.md를 함께 고친다.
