# ADR-012: 비용 시뮬레이터 계산 방식

- 상태: 제안 (2026-11-04, 이슈 #31)

## 배경
- S08은 낭비 추천을 골라 적용하고 트래픽 증가를 가정했을 때 월 비용이 얼마가 되는지, 예산 안에 드는지 보여 준다.
- 프론트는 계산하지 않는다. 같은 계산을 팀 벤치마킹(S09 "추천 적용 후 위치")에서도 쓴다.

## 결정
- 저장하지 않는 계산 API(`POST /simulations`)로 둔다. 추천은 조회할 때 계산되므로 id(`{instanceId}:{kind}`)로 지금 목록에서 다시 찾는다.
  목록에 없는 id는 400 `UNKNOWN_RECOMMENDATION` (추천이 사라졌는데 예전 절감액을 쓰지 않게).
- 기준 금액은 대시보드의 월말 예상이다. 적용 전 = 월말 예상 × (1+g), 적용 후 = (월말 예상 − 고른 절감액 합) × (1+g).
  트래픽이 늘면 서버 사용 시간·비용도 같은 비율로 는다고 단순하게 가정한다 (자동 확장 대수·요청 수는 모른다).
- 절감액은 낭비 추천의 월 절감액(최근 14일 사용 시간을 730시간으로 환산)을 그대로 더한다. 적용 후는 0 아래로 내려가지 않는다.
- 월말 예상이 없으면 `NO_FORECAST`로 금액을 비운다 (0원으로 보이지 않게).
- 체험 모드는 같은 계산을 쓰고, 요청 설정에 추천 id·증가율·예산을 더한다.

## 결과
- 월말 예상은 달력 기준(남은 날), 절감액은 730시간 기준이라 이번 달 남은 기간만의 절감과는 다르다. "매달 절감"으로 안내한다.
- 증가율은 0~100%로 제한한다. 더 큰 값이 필요하면 상수 `CostSimulation.MAX_GROWTH_PERCENT`와 이 ADR을 고친다.
