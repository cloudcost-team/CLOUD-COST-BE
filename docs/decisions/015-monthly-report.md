# ADR-015: 월간 리포트를 조회할 때 계산

- 상태: 제안 (2026-11-05, 이슈 #37)

## 배경
- S10은 달마다 추정 비용·전월 대비·급증일·절감 제안·서버별 비중을 보여 주고, 목록(S10-2)과 상태(S10-4)를 둔다.
- 예약 수집이 없고(ADR-002), 비용·급증·낭비 계산은 이미 domain에 있다.

## 결정
- 리포트를 저장하지 않고 조회할 때 기존 계산(월별·일별 비용, `SpikeDetector`, `WasteDetector`)을 조합한다. 새 테이블이 없다.
- 상태는 EMPTY(사용 기록 없음) → FIRST_MONTH(기록 시작 달) → PREVIEW(이번 달) → FINAL(지난 달) 순서로 정한다.
- 절감 제안은 "그 달 마지막 14일"(다음 달 1일 0시 KST 직전 14일)에 낭비 탐지 규칙을 적용한다. 대상은 지금 남아 있는 서버다.
- 목록은 기록 시작 달 ~ 이번 달, 최대 14개월(조회 기간 455일 제한 안)로 자른다.
- 체험 모드는 설정한 기간의 마지막 날을 오늘로 보고 같은 계산을 쓴다.

## 결과
- 단가 캐시·수집 기록이 바뀌면 지난 달 값도 바뀔 수 있다 ("확정"은 달이 끝났다는 뜻이지 값을 고정한다는 뜻이 아니다). 응답 `notes`로 안내한다.
- 네트워크 지표는 최근 14일만 모으므로(ADR-009) 지난 달의 유휴 판단은 빠질 수 있다. 지운 서버는 절감 제안에 나오지 않는다.
- 기록 시작 달은 대개 달 중간(소급 시작일)부터라, 그다음 달의 전월 대비는 일부 기간과 비교된다.
- 리포트를 고정해야 하면(공유·PDF 등) 그때 월별 스냅샷 테이블을 추가한다.
