# ADR-010: 낭비 리소스 탐지 규칙과 인스턴스 사양 카탈로그

- 상태: 제안 (2026-11-04, 이슈 #10)

## 배경
- 기획(S07)은 리소스별 탐지 근거·추천 조치·월 절감액을 요구한다. 고객 권한은 EC2·CloudWatch 읽기뿐이라 볼륨·IP·스냅샷·로드밸런서는 볼 수 없다.
- 사양 변경 추천에는 타입별 vCPU·메모리가 필요하다. CLAUDE.md §4는 우리 계정의 `ec2:DescribeInstanceTypes`로 조회하라고 하지만,
  그러려면 백엔드 Role 권한 추가와 콘솔 작업이 필요하다.

## 결정
- 판단 구간은 최근 14일(정시 기준), 그 동안 24시간 이상 켜져 있던 서버만 판단한다. 근거는 ADR-009 지표다.
- 유휴: CPU 평균 < 1% + 네트워크 하루 평균 < 5MB → 중지 검토, 절감액 = 월 추정 비용 전부. 네트워크를 모르면 유휴로 보지 않는다.
- 과다 사양: CPU P95(시간 평균 기준) < 10% → t3 패밀리에서 메모리 절반·vCPU 이하 타입으로 변경 검토. 더 싸지 않으면 추천하지 않는다.
- 월 추정 비용 = 최근 14일 사용 시간을 730시간 기준 한 달로 환산 × 온디맨드 단가. 줄인 타입 단가는 같은 OS·테넌시로 Price List에 묻는다.
- **사양은 domain의 고정 카탈로그(`InstanceSpecs`)로 둔다** (t2·t3·t3a, m5·m6i·m7i 계열, c5·c6i·c7i 계열, r5·r6i·r7i 계열, g4dn).
  타입 사양은 바뀌지 않아 조회할 필요가 없다. 카탈로그에 없는 타입과 GPU 타입은 추천하지 않고 이유를 응답에 남긴다.
- 상세 화면(S07-2)용 사양 비교·주의사항·콘솔 변경 방법을 목록 항목에 함께 넣는다 (상세 API를 따로 두지 않는다).
- 추천 id는 `{instanceId}:{kind}`로 결정적으로 만든다. 저장하지 않고 조회할 때마다 계산한다.

## 결과
- 권한·AWS 작업 없이 동작한다. 새 패밀리(m8g 등)는 카탈로그에 한 줄 추가해야 추천 대상이 된다.
- 메모리를 판단하지 못하므로 과다 사양 추천에 "메모리 먼저 확인" 주의사항을 항상 붙인다.
- 체험 모드도 같은 규칙을 쓰고, 단가만 고정 카탈로그(`DemoCatalog`)에서 가져온다.
